# 10. 로그인 기능 계획 (11/17 요청 → **A안 시연용 가상 로그인으로 결정·진행**)

목표: '기업'과 '회계법인 / 세무법인'가 로그인해야만 각자의 화면을 쓸 수 있고, 두 쪽은 서로의 정보를 볼 수 없다. 둘이 만나는 곳은 **기업이 보낸 상담 요청 1가지 통로**뿐이다 (요청을 받은 전문가만 그 요청의 전달 자료를 본다).

## 먼저 알아야 할 충돌
- `CLAUDE.md` 범위에 "로그인·결제 없음", 절대 규칙 5번에 "사용자 입력은 저장하지 않는다"가 있다. 로그인을 넣으면 계정 정보(이름·이메일 등)를 저장하게 되어 이 두 규칙을 바꿔야 한다.
- 배포 서버(Streamlit Community Cloud)는 파일을 영구 저장하지 못한다. 실제 계정을 유지하려면 **외부 데이터베이스**가 필요하다. Claude의 작업 환경은 외부 사이트 접속이 막혀 있어 외부 데이터베이스 연결은 **배포 후에만** 확인할 수 있다.

## 선택지
| | A. 시연용 가상 로그인 (권장) | B. 실제 로그인 |
|---|---|---|
| 방식 | 가상 계정(기업용·세무사용 등)으로 로그인 흉내. 서버에 개인정보 저장 없음 | 구글 로그인(Streamlit 내장 `st.login`) + 외부 데이터베이스에 계정·역할·요청 저장 |
| 보여 주는 것 | 역할별 화면 분리, 로그인 안 하면 서비스 차단, 기업↔전문가 데이터 비공유 | 위와 같고, 실제로 계정이 유지됨 |
| 내가 할 일 | 계정 구성에 동의만 | 구글 OAuth 발급, 데이터베이스 가입·키 입력, 개인정보 문구 검토 |
| 비용·위험 | 없음. 반나절 | 설정이 많고 개인정보 책임이 생김. 며칠, 발표 일정 위험 |
| 12/14 과제 적합도 | 높음 | 낮음 (향후 발전으로 설명) |

## 공통 규칙 (A·B 모두)
1. 로그인하지 않으면 '기업'·'회계법인 / 세무법인' 화면 모두 로그인 안내만 보인다.
2. 계정에는 역할이 하나 붙는다: 기업 또는 전문가. 기업 계정은 전문가 탭을 못 열고, 전문가 계정은 기업 입력·결과 화면을 못 연다.
3. 기업이 입력한 값과 계산 결과는 그 기업 로그인 세션 안에서만 쓴다. 전문가에게는 기업이 "상담 요청 보내기"를 눌렀을 때 전달 자료로만 간다.
4. 전문가는 자기에게 온 요청만 본다 (지금처럼 드롭다운으로 전문가를 고르는 방식은 없어진다).
5. 기업은 다른 기업의 정보를, 전문가는 다른 전문가의 요청을 볼 수 없다.

## 단계
**A를 고른 경우**
- 내가 할 일: A로 진행한다고 알려 주기, 가상 계정 이름 구성 확인 (기본: 기업 2개, 세무사 2개, 회계사 1개), 배포 화면에서 로그인·로그아웃 써 보기.
- Claude가 할 일: `CLAUDE.md`·`docs/01-prd.md`에 범위 변경(시연용 로그인) 반영 → 로그인 화면과 세션 역할 구분 → 역할별 화면 접근 차단 → 전문가 본인 요청만 보이게 변경 → 테스트(기업이 전문가 탭 접근 불가, 로그아웃 시 데이터 삭제 등) → 문서·대시보드·배포.

**B를 고른 경우 (추가로)**
- 내가 할 일: ① 구글 클라우드에서 로그인용 OAuth 클라이언트 만들기(승인된 리디렉션 주소는 Claude가 알려 줌) ② 외부 데이터베이스 서비스 가입(무료 요금제) ③ 발급된 키를 채팅이 아니라 Streamlit Secrets에만 입력 ④ 개인정보 처리방침·동의 문구 확인 ⑤ 전문가 가입 승인 정책 결정.
- Claude가 할 일: 로그인 연동 코드, 계정·역할·요청 테이블 설계, 역할 선택·전문가 승인 흐름, 비밀번호·키를 코드에 쓰지 않는 구성, 개인정보 동의 화면, 배포 후 연결 확인 방법 안내.

## 결정 기록 (11/17)
- A안 선택. 계정은 가상: 기업 2(가상전자(주) 대표, 새싹소프트(주) 대표), 운영자 1, 전문가는 승인된 전문가 전원(세무사·회계사). 공통 비밀번호는 화면에 안내하는 시연용 값이다.
- 역할은 화면을 숨기는 것이 아니라 코드에서 접근을 막는다(기업 계정은 전문가 화면 함수를 실행하지 않음). 로그아웃하면 기업 입력·결과를 지우고, 전문가 명단·상담 요청 보관함은 이 접속 동안 유지한다.
- 한계: 접속(세션)마다 따로 메모리에 있어서 다른 사람의 접속과 요청이 공유되지 않는다. 새로고침하면 처음 상태로 돌아간다. 실제 서비스(B안)에서는 외부 데이터베이스가 이 역할을 한다.
- 전문가 가입 신청은 로그인 전 화면에서 누구나 낼 수 있고(가입 신청), 운영자 계정이 승인하면 그 전문가 계정으로 로그인할 수 있다.


## 11/22 변경 (A안 보완)
- 계정 = 기업명·법인명. 로그인 화면에는 계정 목록이 없고, 이름을 직접 입력해야 한다(없는 이름·틀린 비밀번호는 같은 오류 문구).
- 로그인 / 회원가입은 별도 탭. 기업은 회원가입 즉시 계정 생성, 회계법인/세무법인은 운영자 승인 후 로그인.
- 기업 연락처(이메일·전화)는 가상 형식만 받는다(example.com, 010-0000-XXXX). 상담 요청 전달 자료·PDF에 실려 법인이 연락할 수 있다. 실제 개인정보는 받지 않는다(절대 규칙 5).
