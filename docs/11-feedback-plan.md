2. 외부 공고 API가 실패했을 때 **사용자에게 안내하는 화면**과, 판정 근거로 제시하는 **PDF 출처 표기**를 더 정교하게 다듬는다.

## 1번: 실입력 흐름 검증
1-1. **가입 없이 바로 써 보기(게스트)**: 로그인 화면에 "가입 없이 직접 입력해 계산해 보기" 추가. 계산·공고 추천·해설·PDF까지 가능, 상담 요청만 가입 필요. 입력값은 세션 안에서만 쓰고 저장하지 않는다 (규칙 5와 같은 원칙).
1-2. **입력 검증 강화**: 당해/전년 인원, 청년 ≤ 전체 인원, 매출·자산 단위 오류, 업종·지역 누락 등을 쉬운 말로 안내. 잘못된 값은 계산 전에 막는다.
1-3. **정답 사례 테스트 먼저**: 직접 입력 값 6건(청년 고용 증가, R&D, 창업감면, 중소 특별감면, 중복 배제, 경계값)의 기대값을 손계산으로 만들어 `tests/test_manual_flow.py`에 둔다. 화면(AppTest)에서 값을 타이핑해 엔진 결과와 일치하는지 확인.
1-4. **매칭 검증**: 업종·지역·업력을 바꾸면 추천이 달라지는지, 후보가 0건일 때 안내가 나오는지 테스트.
1-5. **개인정보 안내**: 식별정보(사업자번호·실명 등)는 입력칸이 없음을 화면에 명시. 연락처는 계속 가상 형식만 받는다.

## 2번: API 실패 안내 + PDF 출처 표기
2-1. **데이터 상태 모델** `src/data_sources/status.py`: 출처별 상태(실시간 성공 / 실패→저장본 / 저장본 없음→가상 샘플), 기준일, 건수, 실패 이유(쉬운 말).
2-2. **실시간 확인 시도**: "최신 공고 확인" 버튼으로 K-Startup 호출(시간 제한 있음). 실패하면 저장본으로 대체하고 이유를 알린다. 기업마당은 저장본 기준임을 그대로 표시.
2-3. **실패 안내 화면**: 결과 맨 위 안내 띠(어떤 출처가 실패했고, 어느 날짜 저장본으로 추천했는지, 마감은 원문에서 확인), 공고 카드마다 출처·기준일 표시, 샘플 대체 시 "실제 공고 아님" 강조. 시연용 "외부 API 장애 시연" 스위치(운영자 화면)로 발표 때 실패 상황을 재현.
2-4. **PDF 출처 표기**: 본문 1페이지는 유지하고 **2페이지 부록 "출처·판정 근거"** 추가. 금액별 조문·확인일·확인 여부(미확인 표시), 공고별 출처·공고 번호·원문 링크·수집 기준일·저장본 여부, 데이터 상태 한 줄. 상담 전달 PDF는 1페이지 유지.
2-5. **테스트**: 실패 상태 3종 화면 테스트, PDF 부록 내용·쪽수 테스트.

## 진행 순서 변경 (11/25)
사용자 요청으로 **2-4 PDF 출처 표기를 먼저 구현**했다 (2-1~2-3 데이터 상태 모델·실패 안내 화면은 이어서). 1번의 실입력 검증에는 서류 OCR이 필요할 수 있어, 2번을 끝낸 뒤 범위를 다시 정한다.
- 구현: `src/report/evidence.py`(근거 표 생성) · `src/data_sources/status.py`(저장본 건수·수집일) · `src/tax_engine/registry.py`(카드에 확인일·근거 추가) · `src/report/pdf.py`(2쪽 부록) · 화면 해설 탭 expander
- 부록 내용: A 세액공제 계산 근거(조문·계산식·이번 결과·확인 상태, 미확인 표시) / B 입력값 / C 추천 공고 근거(출처·번호·마감·점수 구성·원문 링크) / D 공고 데이터 기준(저장본 건수·수집일·경과 일수·제외 건수) / E 유의사항
- 설계 이유: 판정 근거를 PDF와 화면이 같은 함수에서 만들어 서로 달라지지 않게 했고, 금액은 엔진 결과를 원 단위로 바꿔 옮길 뿐 새 숫자를 만들지 않는다.
